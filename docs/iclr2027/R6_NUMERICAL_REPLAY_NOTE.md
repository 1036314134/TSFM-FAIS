# R6 inference-layout correction

The first policy run stopped before producing a complete prediction bank or scoring new futures. Module inference and independent matrix replay differed in gate weights by at most 2.3185e-7. The failed evaluator, feature-construction source and logs are retained in `gate-replay-diagnostic-v001`; the partial `policy-results-v001` directory is preserved.

The same actual feature values were tested under three memory layouts. Bulk column-oriented inputs and contiguous inputs gave exact agreement. Concatenated per-episode column-oriented arrays, with byte strides (924, 4, 28), reproduced the discrepancy when the module parameters retained gradient flags. Removing those flags also removed the discrepancy. The evidence identifies a numerical dispatch difference associated with layout and gradient metadata, without attributing it to a particular library kernel that was not inspected.

R6 now packs the unchanged feature values into contiguous float32 arrays before gate inference and independent replay. The gate architecture, parameters, source normalization, candidate forecasts, imputation outputs, selected cases and scoring definition remain unchanged. No tolerance was loosened and no true future error was read to choose this correction. All 18 frozen teacher/member/future-control checkpoints were checked on the same actual feature values; maximum replay difference was zero. Eight related unit checks passed, including a regression for the noncontiguous input layout and existing H96/H192 target handling.

The corrected policy run uses `policy-runtime-check-v002`, `policy-results-v002`, `policy-audit-v002` and `readout-v002`. The original `confirmation-v001/forecasts` banks are reused. The new runtime record refers to the four policy output/layout tests within the eight-test execution, so they are not rerun solely to create another status file. This is an implementation correction before accuracy interpretation, not a change to the frozen primary method or a new independent cohort.
