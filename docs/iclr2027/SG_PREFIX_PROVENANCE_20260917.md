# 新加坡停车场储备：上游前缀抽查

2026年9月17日，对原本地SG_Carpark_15T的354条序列进行只读抽查。原Arrow文件SHA保持不变，起点均为2025-01-01 00:15、频率均为15T。此次只读取最早三个前缀时点，无预测器调用、无预测误差读取，也没有修改其他项目的数据。

公开HDB接口返回了2025-01-01 00:15、00:30、00:45请求对应的最近快照，实际快照时间分别为00:14:26、00:29:27、00:44:27（新加坡时区）。这些结果与“规则时点之前最近可用快照”相容，不能等同于全部传感器恰好在规则时点测量。[官方数据入口](https://data.gov.sg/datasets/d_ca933a644e55d34fe21f28b8052fac63/view)

每个抽查时点都有353/354条本地值与相同车场的C类型可用量精确一致。剩余SB36的本地值均为66，与M类型的可用量一致，而其C类型分别为127、125、123。00:45快照还出现同一SB36标识对应多个类型记录的情况。因此车场标识与车位类型需要共同核对；当前不能把所有序列默认解释为同一种车位测量。三个时点的现象不能证明SB36在整个时期发生了类型切换，也不能据此断言整个集合错误或按未来误差删掉该序列。

本地相关项目中未找到包含carpark_info、lots_available或该API地址的转换脚本。此次抽查增加了原始数值与官方快照的对应证据，但仍没有认证五个月完整的筛选、类型选择、缺失处理和聚合过程。原NaN不能自动称为真实设备故障，预训练重叠也未排除。该集合继续归Singapore已知来源组；新序列、新时段与新来源确认仍应分开。
