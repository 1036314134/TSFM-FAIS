# 审稿人式迭代门槛

这个清单用于审查或生成 `scripts/iteration/iterate_prompt.md`。它提供通用审稿逻辑，不包含任何具体项目事实。

## 每轮先问的问题

1. 这篇论文的必要性是什么？如果没有本文，审稿人会错过什么判断？
2. 方法是否来自问题结构，而不是为了跑赢 baseline 临时拼接？
3. 理论是否能推出可检查的动作、阈值、强度、拒绝条件或失败边界？
4. 实验是否验证“性质 -> 方法 -> 结果”的链条，而不是只证明数据质量会影响模型？
5. 结果数字是否都有真实产物、日志、表格、registry 或定理来源？
6. 摘要第一句是否给出具体发现或问题，而不是“本文研究 X 并提出 Y”？
7. 贡献列表是否改写了已有理解，还是只列举“我们做了三个模块”？
8. 正文是否能被目标领域审稿人直接读懂，不依赖内部计划或自造缩写？

## 证据门槛

任何数字进入摘要、引言贡献、主结果表、图注、结论前，必须满足至少一项：

- 来源于真实运行产物，路径可追溯。
- 来源于确定性理论推导，位置可追溯。
- 明确标为 TBD / protocol / future work，且不作为主结论证据。

如果一个 claim 没有证据，优先删除或降级，不要用更强的形容词掩盖。

## 语言门槛

- 避免机械过渡词连续出现。
- 避免“显著、颠覆性、革命性、前所未有”等无法由证据直接支撑的词。
- 避免把英文内部术语直接翻译成僵硬口号。
- 避免把工程记录词写进摘要、引言、贡献和结论。
- 每段应有明确对象、问题、方法或证据，不要只堆概念名。

## 图表门槛

- 图表必须帮助读者理解方法或证据，不只是占位。
- 数据图优先由 Python 脚本生成，风格在项目内统一。
- 概念图先生成提示词和标签审查，再进入正文。
- 若图是示意图，图注要说明它是否为概念图、是否支撑实验结论。

## 实质增量门槛

一轮迭代至少要改变以下之一：

- 研究问题或必要性表达
- 方法结构或动作空间
- 理论定义、命题或证明
- 真实实验、可追溯结果或实验设计
- 摘要、引言、方法、实验或讨论中的核心叙事

只改错别字、格式、路径、同义词或日志，不构成合格迭代。
